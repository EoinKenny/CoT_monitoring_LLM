# Training-balance comparison and TP/FP sampling audit

Requested 2026-10-04. Compare the existing balanced undersample with class_weight="balanced" against all eligible training examples with class_weight="balanced". Select by observed test positive-class F1 as requested; this is an exploratory model-selection decision, not an independent confirmatory test.

FAVA is the most imbalanced available training pool across the ten datasets: 17,210 positives and 391 negatives. The original three datasets were also checked (WildGuard 6,695 positive / 23,650 negative; HighStakes 4,000 / 3,999; ToxicChat 273 / 3,519). The FAVA comparison uses Llama-3.2-1B-Instruct, a fixed block-11 representation, C=.01, and separately training-fitted standardisers. Both arms tune their thresholds only on the same original validation set, maximising positive-class F1 with highest-threshold tie break. Both are then tested on the exact same original test examples. No PCA or hyperparameter search.

Preparation replays the original FAVA adapter, filtering, grouping and split rules, with training undersampling disabled. Ordered validation/test identities, labels, groups and input hashes are checked against the frozen study. Cached activation vectors are reused for every original example; only the 16,819 excluded majority-class training examples require new extraction. The original balanced arm must reproduce its saved test confusion matrix exactly. The trained probes and full predictions are saved separately. A fixed-seed 2,000-replicate paired group bootstrap describes the conditional test-F1 difference. The always-positive test-F1 baseline is included.

The first extraction attempt failed before generating new vectors because the tokenizer had no padding ID. Its code, status and log are preserved. The second attempt uses the same masked padding ID, 128009, as the original Llama extraction. New GPU allocation is limited to 6.5% of device memory; the existing active judge is allowed to finish and its controller is held before launching another condition.

FLAG_AVAILABILITY.csv records TP/FP populations for all 30 existing backbone/dataset combinations. These are counts from the current probes, not predictions from the as-yet-unselected new training policy. stratified_sampling.py implements deterministic separate per-class quotas and an explicit exact-balance alternative. It has no inference side effects. Judge-sample selection must be frozen after the training policy and thresholds are chosen; do not silently relabel the existing uniform sample as balanced. Full-test cascade estimates must continue to weight acceptance rates by actual TP/FP population counts.

The method selected on FAVA/Llama is not demonstrated to be universally superior on other datasets or backbones. Scaling that choice is an experimental policy choice, and results used for choosing it remain exploratory.
